# 内网配置读取服务 · 服务发现值班台

机房值班员滚动替换配置读取服务实例时, 用来确认"请求究竟由谁应答"的小系统:

- **注册中心**(`registry/`, FastAPI + SQLite): 实例注册/心跳续租/注销, 实例选取与真实转发, 网页值班台
- **配置后端**(`backend/`, FastAPI): 返回预置配置与实例身份, 自动注册+续租, 管理口供故障演练
- **编排**(`docker-compose.yml`): 注册中心 + 两台后端(`config-1` / `config-2`)

## 运行

```bash
docker compose up --build
# 打开值班台 http://localhost:8000
```

无 Docker 时本地运行(需 `pip install fastapi "uvicorn[standard]" httpx`):

```bash
bash run_local.sh        # 注册中心 :8000(守护循环, 支持网页重启), 后端 :8001/:8002
```

## 值班台操作与机制对照

| 需求 | 机制 | 值班台操作 |
|---|---|---|
| 后端自动注册并续租 | 后端启动即注册, 之后每 2s 心跳(租约 8s) | 实例表可见心跳距今/租约剩余 |
| 确认请求由谁应答 | 注册中心在合格实例中轮询选取, 转发真实 `GET /config` | "发送配置请求", 展示所选实例+响应 |
| 租约过期不参与选取 | 选取时校验 `last_heartbeat+ttl` | "暂停心跳" → 约 8s 后该行变红, 请求全落到另一台 |
| 过期不能靠迟到心跳复活 | 过期心跳返回 410, 必须重新注册(epoch+1) | "恢复心跳"后可见 epoch 递增 |
| 同名新进程接替, 旧进程迟到心跳/注销无效 | 进程级 fencing token; 旧 token 心跳/注销一律 409, 记录不动 | "模拟同名重启"后再点"旧进程迟到心跳/注销", 日志可见 409 |
| 注册中心重启后未确认记录不转发 | 记录持久化在 SQLite, 但选取要求 `confirmed_boot == 当前 boot_id`; 只有重启后的心跳/注册才算重新确认 | "重启注册中心"(依赖 docker restart 策略) |
| 无实例/转发失败如实显示 | `no_eligible_instance`(含每台拒绝原因) / `forward_failed` / `upstream_error` | 暂停两台心跳, 或对某台做故障注入(挂起/500) |

## 自测

```bash
python3 tests/selftest.py     # 需系统已在运行(compose 或 run_local.sh)
```

覆盖: 注册续租、轮询转发、过期剔除、410 重新注册、同名接替 fencing(409)、
转发失败/500 如实显示、无实例如实显示、注册中心重启后未确认不转发。

## 关键设计

- **fencing token**: 每个后端进程启动时随机生成 token, 注册即绑定实例名。
  同名新进程注册后旧 token 即刻失效——旧进程迟到的心跳(409)恢复不了旧租约,
  迟到的注销(409)也摘不掉新实例。后端收到 409 会判定自己被接替,
  停止心跳且**不抢注**, 等待处置。
- **租约**: `last_heartbeat + ttl` 过期即不可选; 过期后心跳一律 410, 只能重新注册。
- **重启重新确认**: 注册中心每次启动生成 `boot_id`; 心跳/注册成功会把记录标记为
  当前 boot。重启后旧记录虽在(SQLite 持久化), 但未重新确认前不参与转发。

## 说明

- 选取策略为轮询(便于观察"谁在应答"), 可换成随机/权重。
- "重启注册中心"按钮让进程退出, 依赖 `restart: unless-stopped`(或 `run_local.sh` 的守护循环)拉起。
- 后端"模拟同名重启"是进程内换 token 重注册, 等价于同名新进程接替的注册中心视角效果。
